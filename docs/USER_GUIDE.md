# 使用指南

完全在 Windows 电脑本地运行的饮食、体重和身体数据管理应用。安装版和便携版均不需要账号、浏览器地址或服务器；应用运行时不依赖网络，记录默认只保存在当前电脑。

## 当前已完成功能（0.7.1）

- Electron 桌面窗口：单实例运行，支持最小化、最大化、关闭，并记住上次窗口大小和可见位置。
- 今日记录：日期前后切换、日历选日、返回今天、体重/体脂率/腰围快速记录。
- 四个餐次与补剂记录：早餐、午餐、晚餐和加餐均可新增、编辑、删除、清空及拖动排序食物；补剂记录作为独立分区与四餐并列，也支持新增、编辑、删除、清空和排序。
- 添加食物：弹窗内搜索，支持按克或按份记录；未找到时可直接创建食物并继续加入当前餐次。
- 数量输入：按份、个、杯、片、粒等均可手动填写小数；加减按钮及上下方向键按份每次增减 1，保留已有的小数部分。按克每次增减 0.1 克，自动保留一位小数，整数会显示为 `3.0`。新增、编辑、常用组合和补剂计划使用相同规则。
- 餐次分配：每个饮食方案可设置早、中、晚餐比例，热量和三大营养素按同一比例拆分；前餐超额会逐餐挤占后续额度，最多顺延到晚餐。
- 摄入量推荐：食物种类由用户选择，在填写数量时可按本餐剩余目标推荐该食物的摄入量；推荐记录会随本餐后续食物自动调整，手动编辑后转为固定用量。
- 加餐与放纵餐：加餐营养从记录当时尚未填写的第一顿正餐扣除，三餐均已填写时扣除晚餐；早、中、晚餐可设为放纵餐，直接按动态目标记满且不保存具体食物。
- 实时营养统计：按历史快照汇总热量、蛋白质、碳水和脂肪，显示目标、完成比例、剩余量或超出量。
- 热量单位换算：新建或编辑食物、补剂和饮食方案时，可在“千卡 (kcal)”与“千焦 (kJ)”之间切换，输入值会按 `1 kcal = 4.184 kJ` 自动换算。
- 食物库：独立管理普通食物，支持搜索、分类筛选、新增、编辑、复制和停用；补剂不会再混入普通食物列表。
- 补剂库：独立管理肌酸、电解质冲粉、蛋白粉、锌镁片、复合维生素、鱼油和谷氨酰胺等补剂，支持搜索、新增、编辑、复制和删除，并可设置按需、每天或每周指定日服用，以及每次按克或按份的用量。删除不会破坏历史快照；默认补剂带有可修改的作用说明，四项营养从 0 开始；鱼油、蛋白粉等需按本人产品标签填写并自行决定是否计入营养统计。
- 补剂计划推荐：今日记录按所选日期列出当天到期的补剂计划，可按预设用量一键写入补剂记录；按需补剂仍可手动添加，不会自动进入计划推荐。
- 身体数据：新增、编辑、删除、日期筛选、重复日期覆盖和复制上一条记录。
- 饮食方案：新建、编辑、复制、切换和删除；方案名称、目标类型、使用日期和备注作为同一组公共信息管理。
- 日型计划：每个饮食方案可包含“训练日”“休息日”“高碳日”“低碳日”等日型；每个日型分别保存手动目标，或按每公斤蛋白质、碳水、脂肪系数自动跟随最新有效体重。直接手动输入计算体重会关闭自动更新。同一天只采用一个日型，首个日型负责尚未单独选择的日期，不再额外并列一份“主方案默认”。
- 本地 SQLite：首次启动自动建库并按 migration 升级；食物修改或停用不会改变既有饮食记录的营养快照。
- 快捷操作：`Ctrl + N` 添加食物、`Ctrl + W` 记录体重、`Ctrl + F` 在今日记录中打开食物搜索。
- 搜索与常用食物：支持名称、品牌和拼音首字母搜索；添加食物弹窗可切换“最近使用”和“常用食物”，食物库可直接收藏或取消收藏。
- 常用组合：支持创建、编辑和删除多食物组合，组合只包含普通食物，分别设置克数或份数，并一键加入指定日期的早餐、午餐、晚餐或加餐；补剂通过独立分区记录。
- 饮食复制：首页支持复制昨天全天，四个餐次支持复制昨天同餐；全天复制和历史记录中的部分记录复制均包含补剂记录。
- 复制冲突处理：目标餐次已有记录时可选择追加或覆盖；覆盖只处理选中的餐次，其他餐次保持不变。
- 历史记录：按日汇总体重、体脂率、腰围和四项营养，可按日期、饮食方案、热量达标状态及蛋白质达标状态筛选，并查看四餐与补剂记录明细。
- 每日方案快照：首次写入当天身体或饮食数据时保存方案、日型名称与目标；以后编辑、删除日型或切换方案不会改写过去日期，显式切换当天日型会更新当天快照。
- 趋势图表：提供体重、体脂率、腰围、四项营养、摄入与目标对比、每周平均体重和每周平均热量图表；支持悬停明细、图例显隐和时间轴缩放。
- 时间分析：支持最近 7/30/90 天、本月、今年和自定义日期；身体趋势可切换 7/14/30 日移动平均，缺失日期和缺失指标不会按 0 补齐。
- 图表导出：每张图表可保存为 PNG 或 SVG，并可导出与当前曲线一致的 CSV，包含移动平均、目标对比或每周平均等派生数据。
- Excel 导出：生成包含身体数据、每日饮食明细、每日营养汇总、食物库、饮食方案和常用组合的 6 工作表 `.xlsx` 文件；补剂记录包含在每日饮食明细中，补剂计划包含在食物库中。
- CSV 导入导出：六类数据可分别导出 UTF-8 CSV；每日饮食明细包含补剂记录，食物库 CSV 包含补剂计划字段；身体数据和食物库支持导入，全部行验证成功后才在事务中写入。

## 主要功能操作

- 管理补剂：进入“补剂库”查看七种默认补剂。新增或编辑补剂时可选择“按需”“每天”或“每周指定日”，并为每天或指定星期的计划填写每次用量；用量选择“份”时还必须填写包装标示的每份重量。新增补剂的热量、蛋白质、碳水和脂肪均默认为 0；鱼油、蛋白粉、电解质冲粉等产品配方不同，应按实际标签填写后再开启“计入营养统计”。补剂作用说明仅供记录参考，不属于医疗建议。
- 记录补剂：进入“今日记录”底部的“补剂记录”分区，查看所选日期到期的补剂计划；点击“一键记录”会按补剂库中设置的每次用量写入，已记录的计划会显示完成状态。按需补剂可点击“添加记录”手动加入；开启“计入营养统计”的补剂会按保存时的营养快照计入当天汇总。
- 生成饮食目标：尚未建立日型时，可在方案目标中选择“按体重系数生成”；建立训练日、休息日等日型后，在“管理日型”中分别编辑每个日型。默认自动采用最新有效体重，新增、修改、导入或删除体重记录后会重新计算自动来源的方案和日型；直接改写计算体重会切换为手动来源。默认碳水 3、蛋白质 2、脂肪 1 g/kg。
- 设置日型计划：在同一饮食方案中建立训练日、休息日等日型，并分别保存计算方式、体重来源、三项系数、四项目标和备注；在“今日记录”切换到目标日期后直接选择日型。每个日期独立保存选择，首个日型用于尚未单独选择的日期；旧版本日型保留原目标并按手动填写解释。
- 填写热量：食品包装使用千焦时，在热量输入框右侧选择“千焦 (kJ)”后直接照标签填写；应用会实时显示对应千卡。数据库、历史快照以及 CSV/Excel 继续统一使用 kcal，保证既有数据和导入导出格式兼容。
- 查看趋势：进入“趋势图表”，选择预设或自定义日期范围；身体图表上方可切换 7/14/30 日移动平均。点击图例可隐藏或显示曲线，拖动图表底部滑块可缩放时间范围。
- 导出图表：在对应图表右上角点击 `PNG`、`SVG` 或 `CSV`，再选择本机保存位置。PNG 使用双倍分辨率生成，图片和数据都不会上传网络。
- 导出数据：进入“数据导入导出”，可设置开始和结束日期；留空表示全部日期。完整 Excel 一次生成 6 个工作表，也可分别导出六类 CSV。
- 导出日期范围只筛选身体数据、每日饮食明细和每日营养汇总；食物库、饮食方案和常用组合始终完整导出。
- 导入数据：在“导入 CSV”区域选择身体数据或食物库，阅读覆盖/追加说明并确认，再选择文件。身体数据按日期新增或覆盖，食物库始终追加为新食物。

## CSV 导入模板与规则

建议先从应用导出“身体数据”或“食物库”CSV，再复制其表头和格式填写。身体数据表头必须依次为：

```text
日期,体重(kg),体脂率(%),腰围(cm),备注
```

食物库表头必须依次为：

```text
名称,品牌,分类,每100克热量(kcal),每100克蛋白质(g),每100克碳水(g),每100克脂肪(g),默认每份重量(g),份单位,是否补剂,是否计入营养统计,是否常用,是否可推荐,补剂服用频率,补剂服用星期,补剂每次用量,补剂用量单位,是否停用,备注
```

- 文件必须是 `.csv`，大小不超过 20 MB；新格式使用上面的固定 19 列。旧版固定 15 列食物 CSV 仍可直接导入，缺少的补剂计划字段会按“按需”、无指定星期、无每次用量和“克”处理。
- 日期使用 `YYYY-MM-DD`。身体数据的体重、体脂率和腰围允许留空；数值必须满足应用现有校验，不能填写负数。
- 食物名称、分类和四项每 100 克营养值必填；分类必须使用应用内分类。导入行的分类为“补剂”或“是否补剂”为“是”时，该条目会显示在补剂库。布尔字段建议填写“是”或“否”，也接受 `true/false` 与 `1/0`。
- 补剂服用频率填写“按需”“每天”或“每周指定日”；指定星期可用“周一、周三”等顿号、逗号或空格分隔。每天或每周指定日必须填写每次用量；用量单位填写“克”或“份”，使用“份”时必须同时填写默认每份重量。
- 字段包含逗号、英文双引号或换行时必须使用标准 CSV 引号规则。应用导出的 CSV 已带 UTF-8 BOM，可直接在 Windows Excel 中打开中文内容。
- 同一份身体 CSV 内不能出现重复日期；数据库已有同日记录时覆盖。食物导入不会按名称合并，重名食物也会作为新记录追加。
- 应用先验证全部行，再开启数据库事务；任意一行格式错误、日期无效或数值非法时整批不写入。

## 第二阶段功能操作

- 最近与常用：在“今日记录”点击任一餐次的“添加食物”，使用弹窗顶部的“最近使用”或“常用食物”；进入“食物库”后，点击食物行右侧的星标可切换常用状态。
- 常用组合：进入“食物库 → 常用组合”，点击“新增组合”并逐项设置食物、克数或份数；保存后选择日期和餐次，再点击“一键加入”。组合加入后仍是独立饮食记录，可在首页分别编辑。
- 复制与历史：首页的“复制昨天饮食”用于复制包含补剂记录的全天数据，四个餐次的“复制昨天同餐”只复制对应餐次；“历史记录”页面可查看四餐和补剂明细，并把选中的餐次或补剂记录复制到指定日期。目标已有记录时必须明确选择“追加到现有记录”或“覆盖所选餐次”。

## 普通用户使用

普通用户不需要安装 Node.js、npm、SQLite、数据库管理软件或任何服务器。获得构建好的文件后，直接使用其中一种方式：

- `DietTracker-Setup.exe`：按安装向导完成安装，再双击桌面快捷方式。
- `DietTracker-Portable.exe`：无需安装，放在有写入权限的位置后直接双击。

当前项目没有配置商业代码签名，本地构建的 `.exe` 可能触发 Windows SmartScreen 提示。应用本身不会要求注册或登录。

## 本地数据位置

数据库文件名为 `diet-tracker.sqlite3`，程序通过 Electron 的 `app.getPath('userData')` 获取数据目录。Windows 正常安装环境下通常位于：

```text
C:\Users\<你的用户名>\AppData\Roaming\diet-tracker\diet-tracker.sqlite3
```

Electron 运行时返回的 `userData` 目录是最终依据。开发模式、Windows 用户名或安装环境不同，目录可能变化。数据库与安装目录分离，卸载程序不会主动删除该文件；第四阶段的备份和恢复完成前，请勿把手工复制数据库描述为应用内备份功能。

## 安全架构

页面只能通过 preload 暴露的业务方法访问主进程：

```text
React 页面 → preload 白名单 API → IPC 参数校验 → Electron 主进程 → SQLite
```

- `contextIsolation` 已开启，`nodeIntegration` 已关闭，渲染进程 `sandbox` 已开启。
- React 页面不能直接访问 Node.js、文件系统或 SQLite。
- IPC 写入参数由 Zod 在主进程边界校验，数据库同时使用约束、参数绑定和事务。
- 外部页面跳转及新窗口默认被阻止。
