# 饮食与体重记录助手

一个在 Windows 本地运行的饮食、补剂与身体数据管理工具。记录四餐、查看营养摄入、跟踪体重变化，并按自己的训练日或休息日设置目标。

**当前版本：0.7.3 · Windows x64 · 无需账号 · 可离线使用**

[下载最新版本](https://github.com/lsx20040710/diet-tracker/releases/latest) · [详细使用指南](docs/USER_GUIDE.md) · [更新日志](CHANGELOG.md)

## 下载与安装

在 [Releases](https://github.com/lsx20040710/diet-tracker/releases) 的附件中选择：

| 文件                       | 使用方式                                           |
| -------------------------- | -------------------------------------------------- |
| `DietTracker-Setup.exe`    | 安装版，按向导安装，可创建桌面与开始菜单快捷方式。 |
| `DietTracker-Portable.exe` | 便携版，无需安装，直接双击运行。                   |
| `SHA256SUMS.txt`           | 安装包的 SHA-256 校验值，用于核对下载文件。        |

支持 Windows 10 / 11 x64。普通用户无需安装 Node.js、数据库或服务器。仓库为私有时，需要有仓库访问权限才能下载附件。

当前安装包未配置商业代码签名，Windows 可能显示 SmartScreen 提示。请确认文件来自本仓库的 Release，并按需核对校验值。

## 主要功能

- **每日饮食**：早餐、午餐、晚餐、加餐分区记录，查看热量与营养摄入，支持编辑、排序和复制历史记录。
- **食物库**：关键词、拼音搜索和分类筛选，支持收藏、常用组合、按克或按份计量。
- **数量输入**：按份计量允许手动输入小数，加减按钮和上下方向键每次增减 1 份；按克每次增减 0.1 克。
- **补剂管理**：独立记录补剂，支持补剂计划、计划用量与实际摄入对照。
- **饮食方案**：训练日、休息日与自定义方案；支持日期切换及营养目标快照。
- **餐次分配**：设置早、中、晚餐比例，查看剩余额度，并计算已选食物的建议用量。
- **身体数据**：记录体重、体脂率和腰围，查看趋势与历史数据。
- **数据交换**：支持 CSV / Excel 导入导出，便于整理食物库、身体数据与饮食记录。
- **数据位置可选**：在设置中选择并更改记录存放目录，显示实际路径，安全迁移或明确切换已有数据库，重启后继续使用所选位置。

## 第一次使用

1. 打开“设置”，查看实际数据目录；如需更改，点击“选择数据存放目录”并确认。
2. 打开饮食方案，设置自己的营养目标及餐次比例。
3. 在食物库中添加常吃的食物，核对营养值的计量基准。
4. 回到今日记录，选择餐次、食物和用量；常吃的搭配可保存为组合。
5. 有补剂需求时，在独立补剂分区记录实际用量，或应用已有补剂计划。
6. 记录身体数据并定期导出需要保留的记录。

例如，按份计量时输入 `1.5`，点击加号得到 `2.5`，点击减号得到 `0.5`。小数输入有效，快捷按钮仍按整份变化。

| 快捷键     | 操作                 |
| ---------- | -------------------- |
| `Ctrl + N` | 添加饮食记录         |
| `Ctrl + W` | 快速记录体重         |
| `Ctrl + F` | 搜索今日记录中的食物 |
| `Ctrl + E` | 打开导入导出页面     |

更详细的操作、导入字段和计算说明见 [使用指南](docs/USER_GUIDE.md)。

## 数据与隐私

应用运行时不依赖网络，记录保存在用户选择目录中的 SQLite 数据库，不需要账号。打开“设置 → 用户数据存放位置”，可以查看、复制当前实际目录和数据库文件路径，再通过“选择数据存放目录”更改。选择目录后需要确认才会生效，取消选择不会改变数据。

- 所选目录没有数据库时，迁移当前全部记录；新数据库验证通过并保存目录选择后，清理本次迁移的原数据库及其 WAL/SHM 文件，其他文件不删除。迁移前置步骤失败时保留原数据。
- 若切换到新位置成功但原数据库清理失败，设置页会持续显示待处理告警、当前数据库和原数据库的实际路径，刷新或重启后仍可查看；请核对原路径文件并按需手动处理。
- 所选目录已有数据库时，需要明确确认使用其中的数据。这是切换到另一套数据，两处数据不会合并或覆盖，原数据库不会删除。
- 更改成功后页面重新加载，应用记住所选目录，重启和重新安装后继续使用，无需再次迁移。后续写入只进入当前目录。
- 外接硬盘或原目录不可用时，启动会提示恢复；请先连接设备再重试，或明确选择可用的已有数据库目录。应用不会静默新建空库替代丢失的记录。

数据库文件名为 `diet-tracker.sqlite3`，初始建议目录在 Windows 上通常为：

```text
%APPDATA%\diet-tracker
```

初始建议目录由 Electron 的 `app.getPath('userData')` 提供；开发模式或不同安装环境下可能变化。默认应用目录中的 `data-storage.json` 保存目录选择和最近迁移状态，用户记录数据库存放在所选目录。以设置页显示的实际路径为准。迁移只清理本次原数据库及其 WAL/SHM 文件，旧配置的小型 JSON 副本、已有数据库打开前的安全副本和其他应用文件仍保留。

- 数据库与安装目录分离，卸载程序不会主动删除记录。
- 修改食物或饮食方案时，已保存记录保留自己的营养与目标快照。
- CSV / Excel 导出文件由用户保存在本地，请自行妥善保管。
- 仓库排除个人数据库、导出文件、环境变量、凭据、日志和临时测试目录；安装包只作为 Release 附件发布。
- 应用内完整备份与恢复尚未完成，导出表格不等同于完整数据库备份。

## 开发与构建

技术栈：Electron、React、TypeScript、Vite、Tailwind CSS、Zustand、SQLite、Recharts、Zod 与 ExcelJS。

建议在 Windows x64 上使用 Node.js 24 和 pnpm，依赖版本由 `pnpm-lock.yaml` 固定：

```powershell
git clone https://github.com/lsx20040710/diet-tracker.git
cd diet-tracker
pnpm install --frozen-lockfile
pnpm dev
```

| 命令                | 用途                                           |
| ------------------- | ---------------------------------------------- |
| `pnpm dev`          | 启动开发环境                                   |
| `pnpm build`        | 类型检查并构建应用                             |
| `pnpm dist`         | 构建 Windows 安装版和便携版，输出到 `release/` |
| `pnpm test`         | 运行自动化测试                                 |
| `pnpm typecheck`    | 检查 TypeScript 类型                           |
| `pnpm lint`         | 检查代码规范                                   |
| `pnpm format:check` | 检查格式                                       |

也可使用 npm 执行对应脚本；如需复现锁定的依赖版本，请使用 pnpm。PowerShell 限制 npm 脚本执行时，可使用 `npm.cmd`。

渲染页面通过 preload 白名单 API 访问主进程，开启上下文隔离和渲染进程沙箱，关闭 Node.js 集成；主进程使用 Zod 校验输入，并通过参数绑定与事务访问数据库。测试使用独立的临时数据库。
